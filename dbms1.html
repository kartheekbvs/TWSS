Unit I: Introduction to DBMS

Database System

A database is a collection of related data and data is a collection of facts and figures that can be processed to produce information.

Characteristics of DBMS

  • Real-world entity - Uses real-world entities to design architecture
  • Relation-based tables - Entities and relations form tables
  • Isolation of data and application - Database is different from its data
  • Less redundancy - Follows normalization rules
  • Consistency - Maintains consistent state across relations
  • Query Language - Efficient data retrieval and manipulation
  • ACID Properties - Atomicity, Consistency, Isolation, Durability
  • Multiuser and Concurrent Access - Supports parallel access
  • Multiple views - Different views for different users
  • Security - Methods to impose constraints and protect data

Database Users

  • Administrators - Maintain and administer the DBMS
  • Designers - Design the database structure
  • End Users - Use the database for various purposes

DBMS Architecture

The design of a DBMS depends on its architecture. It can be centralized or decentralized or hierarchical.

  • 1-tier architecture - User directly sits on the DBMS
  • 2-tier architecture - Application through which DBMS is accessed
  • 3-tier architecture - Separates tiers based on complexity

3-tier Architecture Components

  • Database (Data) Tier - Database resides with query processing languages
  • Application (Middle) Tier - Application server and programs accessing the database
  • User (Presentation) Tier - End-users operate on this tier

Data Models

Data models define how the logical structure of a database is modeled.

  • Entity-Relationship Model - Based on real-world entities and relationships
  • Relational Model - Data stored in tables called relations

Database Schema vs Instance

  • Database Schema - Skeleton structure representing logical view of database
  • Database Instance - State of operational database with data at any given time

Data Independence

  • Logical Data Independence - Ability to change logical schema without changing external schema
  • Physical Data Independence - Ability to change physical schema without changing logical schema

Advantages of DBMS

  • Controlling Data Redundancy
  • Sharing of Data
  • Data Consistency
  • Integration of Data
  • Integration Constraints
  • Data Security
  • Control Over Concurrency
  • Backup and Recovery Procedures
  • Data Independence

Disadvantages of DBMS

  • Cost of software/hardware and migration
  • Problem associated with centralization
  • Complexity of Backup and Recovery

Unit II: Relational Model and SQL

Relational Model Concepts

Relational model can represent as a table with columns and rows. Each row is known as a tuple. Each table column has a name or attribute.

Key Concepts

  • Domain - Set of atomic values that an attribute can take
  • Attribute - Name of a column in a table
  • Tuple - Row in a table
  • Relation - Table with columns and rows
  • Null Values - Represents missing or unknown information

Example: STUDENT Relation

NAME ROLL_NO PHONE_NO ADDRESS AGE
Ram 14795 7305758992 Noida 24
Shyam 12839 9026288936 Delhi 35
Laxman 33289 8583287182 Gurugram 20

Properties of Relations

  • Name of the relation is distinct from all other relations
  • Each relation cell contains exactly one atomic value
  • Each attribute contains a distinct name
  • Attribute domain has no significance
  • Tuple has no duplicate value
  • Order of tuple can have different sequence

NULL Values in SQL

The SQL NULL is the term used to represent a missing value. A NULL value in a table is a value in a field that appears to be blank.

CREATE TABLE CUSTOMERS(
  ID INT NOT NULL,
  NAME VARCHAR (20) NOT NULL,
  AGE INT NOT NULL,
  ADDRESS CHAR (25),
  SALARY DECIMAL (18, 2),
  PRIMARY KEY (ID)
);

Integrity Constraints

Integrity constraints are a set of rules used to maintain the quality of information.

  • Domain constraints - Definition of valid set of values for an attribute
  • Entity integrity constraints - Primary key value can't be null
  • Referential Integrity Constraints - Foreign key must be null or match primary key in referenced table
  • Key constraints - Keys used to identify entities uniquely

SQL Functions

String Functions

  • LOWER - Converts string to lowercase
  • UPPER - Converts string to uppercase
  • INITCAP - Converts string to mixed case
  • LENGTH - Returns length of string
  • CONCAT - Concatenates strings

Numeric Functions

  • ABS - Returns absolute value
  • CEIL - Returns smallest integer greater than or equal to number
  • FLOOR - Returns largest integer less than or equal to number
  • ROUND - Rounds a number to specified decimal places

Date Functions

  • ADD_MONTHS - Adds months to a date
  • MONTHS_BETWEEN - Returns months between two dates
  • LAST_DAY - Returns last day of month

Conversion Functions

  • TO_CHAR - Converts date/number to string
  • TO_DATE - Converts string to date
  • NVL - Replaces NULL with specified value

SQL Data Definition Language

CREATE TABLE

CREATE TABLE table_name (
  column1 datatype,
  column2 datatype,
  column3 datatype,
  .....
  columnN datatype,
  PRIMARY KEY( one or more columns )
);

DROP TABLE

DROP TABLE table_name;

SQL Data Manipulation Language

INSERT INTO

INSERT INTO TABLE_NAME (column1, column2, column3,...columnN)
VALUES (value1, value2, value3,...valueN);

SELECT Statement

SELECT column1, column2, columnN FROM table_name;

SELECT * FROM table_name;

WHERE Clause

SELECT column1, column2, columnN
FROM table_name
WHERE [condition];

AND & OR Operators

SELECT column1, column2, columnN
FROM table_name
WHERE [condition1] AND [condition2]...AND [conditionN];

Unit III: Entity Relationship Model and Advanced SQL

Entity Relationship Model

Entity-Relationship (ER) Model is based on the notion of real-world entities and relationships among them.

Key Concepts

  • Entity - Real-world object with properties called attributes
  • Attribute - Property of an entity
  • Entity Set - Collection of similar entities
  • Relationship - Association among entities
  • Relationship Set - Collection of similar relationships

Mapping Cardinalities

  • One to one
  • One to many
  • Many to one
  • Many to many

Advanced SQL Features

Creating Tables with Relationships

CREATE TABLE Department (
  dept_id INT PRIMARY KEY,
  dept_name VARCHAR(50)
);

CREATE TABLE Employee (
  emp_id INT PRIMARY KEY,
  emp_name VARCHAR(50),
  dept_id INT,
  FOREIGN KEY (dept_id) REFERENCES Department(dept_id)
);

Nested Queries and Subqueries

SELECT emp_name FROM Employee
WHERE dept_id = (SELECT dept_id FROM Department WHERE dept_name = 'IT');

Grouping and Aggregation

SELECT dept_id, COUNT(*) as employee_count
FROM Employee
GROUP BY dept_id;

Joins

-- Inner Join
SELECT Employee.emp_name, Department.dept_name
FROM Employee
INNER JOIN Department ON Employee.dept_id = Department.dept_id;

-- Left Join
SELECT Employee.emp_name, Department.dept_name
FROM Employee
LEFT JOIN Department ON Employee.dept_id = Department.dept_id;

Views

CREATE VIEW EmployeeView AS
SELECT emp_id, emp_name, dept_name
FROM Employee
JOIN Department ON Employee.dept_id = Department.dept_id;

Relational Set Operations

  • UNION - Combines results of two SELECT statements
  • INTERSECT - Returns common rows from two SELECT statements
  • EXCEPT/MINUS - Returns rows from first SELECT not in second SELECT

Unit IV: Schema Refinement (Normalization)

Purpose of Normalization

Normalization is the process of organizing data in a database to reduce redundancy and improve data integrity.

Functional Dependency

A functional dependency is a constraint between two sets of attributes in a relation from a database.

Normal Forms

First Normal Form (1NF)

A relation is in 1NF if it contains no repeating groups and all attributes contain atomic values.

Second Normal Form (2NF)

A relation is in 2NF if it is in 1NF and every non-key attribute is fully dependent on the primary key.

Third Normal Form (3NF)

A relation is in 3NF if it is in 2NF and no non-key attribute is transitively dependent on the primary key.

Boyce-Codd Normal Form (BCNF)

A relation is in BCNF if for every non-trivial functional dependency X → Y, X is a superkey.

Fourth Normal Form (4NF)

A relation is in 4NF if it is in BCNF and has no multi-valued dependencies.

Fifth Normal Form (5NF)

A relation is in 5NF if it is in 4NF and cannot be decomposed into smaller tables without loss of information.

Surrogate Key

A surrogate key is a unique identifier for an entity in the database that is not derived from application data.

Lossless Join and Dependency Preservation

  • Lossless Join - Ensures that no information is lost when decomposing relations
  • Dependency Preservation - Ensures that all functional dependencies are preserved after decomposition

Unit V: Transaction Concept and Indexing Techniques

Transaction Concept

A transaction is a sequence of operations performed as a single logical unit of work.

Transaction States

  • Active - Initial state, transaction stays while executing
  • Partially Committed - After final statement
  • Committed - After successful completion
  • Failed - After normal execution discovers error
  • Aborted - After transaction has rolled back

ACID Properties

  • Atomicity - All operations in a transaction succeed or none
  • Consistency - Transaction takes database from one consistent state to another
  • Isolation - Concurrent transactions don't interfere with each other
  • Durability - Once committed, changes persist even in case of failure

Concurrent Executions

Multiple transactions executing simultaneously can lead to inconsistencies. Concurrency control mechanisms ensure consistency.

Serializability

A schedule is serializable if it is equivalent to some serial schedule of the transactions.

Recoverability

A schedule is recoverable if for each pair of transactions Ti and Tj, if Tj reads a data item previously written by Ti, then the commit operation of Ti appears before the commit operation of Tj.

Failure Classification

  • Transaction failure - Logical errors or system errors during transaction
  • System crash - Power failure or hardware malfunction
  • Disk failure - Loss of data on disk

Recovery Techniques

  • Log-based recovery - Uses log records to undo/redo transactions
  • Checkpoint - Point in the execution sequence where database is consistent

Indexing Techniques

B+ Trees

B+ Trees are balanced tree structures that provide efficient access to data. They are commonly used for database indexing.

B+ Tree Operations

  • Search - Efficiently locate data items
  • Insert - Add new entries while maintaining balance
  • Delete - Remove entries while maintaining balance

File Organization and Indexing

  • Cluster Indexes - Determine physical order of data
  • Primary Indexes - Index on primary key
  • Secondary Indexes - Index on non-primary key attributes

Hash-Based Indexing

Hash indexing uses a hash function to compute the location of data items. It provides fast access for exact-match queries.

Comparison of File Organizations

File Organization Advantages Disadvantages
Heap File Simple, fast for loading Slow for searching
Sorted File Fast for range queries Slow for inserts/updates
Hash File Fast for exact matches Not suitable for range queries
B+ Tree Good for all operations Overhead for maintenance

Indexes and Performance Tuning

Proper indexing is crucial for database performance. Indexes speed up queries but slow down insert, update, and delete operations.
